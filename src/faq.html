01 四步完成第一次导表

  1. 准备项目和运行环境

    拿到完整的 SVN 工作副本及项目导表脚本。安装 TortoiseSVN 时包含命令行组件；脚本所需的 Python 等环境，以项目提供的说明为准。

  2. 填写路径，切换到正确版本

    点击主界面「路径设置」，选择「配置表生成目录」和「工具执行目录」。填写后先「保存修改」，再「切换至该版本」。

  3. 保存 Excel，确认本次导出范围

    在 Excel / WPS 中保存修改，回到工具点击「刷新状态」。检查蓝色强制增量和红色不导表标记，按需恢复自动判断。

  4. 导表成功后，再核对并提交 SVN

    日常优先点击「增量导表」。看到成功提示后，再点击「提交SVN」，检查文件、填写说明，并在 SVN 窗口完成提交。

02 路径与版本

两个目录分别选哪里？

配置表生成目录：选择直接包含 config.xml 的「配置表生成」文件夹。Excel 来源目录目前按它的同级「数据填表」文件夹查找。

项目设计目录
├─ 配置表生成   ← 第一个目录，里面有 config.xml
│  └─ config.xml
└─ 数据填表     ← 里面是实际填写的 Excel 文件

工具执行目录：选择实际导表批处理所在的文件夹。脚本名称默认为 toClientPy1.bat，应与项目提供的真实文件一致。

设置页下方会显示推导出的配置文件、Lua、XML 和客户端输出路径。切换前核对它们是否属于你要操作的项目版本。
已经保存路径，为什么界面还是旧版本？

「保存修改」保存配置；「切换至该版本」才会把该版本应用到当前导表界面。两步都操作后，核对主界面右下角版本名和日志中的配置路径。

多个分支可以分别建立版本配置。强制增量、不导表标记按版本保存；切换版本后请重新检查导出范围。

提示找不到 config.xml、Excel 或导表脚本怎么办？
  1. 从错误提示中确认缺少的是哪个文件以及完整路径。
  2. 检查第一个目录是否直接包含 config.xml，同级是否存在「数据填表」。
  3. 检查工具执行目录里是否存在设置中的批处理文件；不要只复制一个 exe 就以为项目导表脚本也已包含。
  4. 若是单个 Excel 缺失，核对配置中 input 的相对路径与实际文件，再保存并切换版本。

03 SVN 环境

安装了“小乌龟”，为什么还提示缺少 svn.exe？

右键菜单和 SVN 命令行组件是不同功能。工具依靠 svn.exe 识别哪些 Excel 已修改；仅有右键菜单并不足够。

  1. 重新运行 TortoiseSVN 安装程序，已安装时选择 Modify（修改）。
  2. 将 command line client tools 设置为安装到本机，完成安装。
  3. 回到工具点击「重新检测」；仍未识别时关闭并重新启动工具。

如安装在自定义目录，请确认 svn.exe 所在目录已加入 PATH，再重启工具。可在新打开的命令提示符中运行 svn --version --quiet 检查。

缺少 SVN 命令行工具时，先修复环境再导表，避免把检测失败误认为没有修改。
提示不是 SVN 工作副本，或修改状态检测失败？

确认选的是通过 SVN 检出的项目目录，而不是从聊天附件或压缩包中单独复制出来的 Excel 文件夹。

先在该目录用 TortoiseSVN 检查工作副本状态。若提示锁定、损坏或冲突，按 SVN 提示处理；不确定时把完整错误交给项目维护人员。回到工具后点击「刷新状态」。

「更新SVN」和「刷新状态」有什么不同？

更新SVN：拉起 SVN 更新流程，获取仓库内容；若出现冲突，需要先处理。

刷新状态：重新读取本地文件的 SVN 修改状态，更新卡片和增量队列，不等于下载仓库的新内容。

04 选择与导表

左侧方框的三个状态分别是什么意思？

连续点击同一个方框，按以下顺序循环：

□ 自动判断按 SVN 修改状态决定是否加入增量；检测到修改时卡片标黄。
✓ 强制增量即使 SVN 未检测到修改，也将该 Excel 加入增量导出。
⊘ 不导表全量和增量都跳过该 Excel。再次点击恢复自动判断。

从自动判断开始，第一次点击进入强制增量，第二次进入不导表，第三次恢复自动判断。也可以右键卡片直接选择状态。

按整个 Excel 文件生效。Sheet 模式中的同一个工作簿也会同步切换，不能用这里的勾选单独排除某个 Sheet。
红色“不导表”会自动恢复吗？全量导表也会跳过吗？

不会自动恢复，全量也会跳过。红色边框、禁止符号和“不导表”标签表示该文件被主动排除。列表上方会显示排除的 Excel 文件数量。

标记按版本保存在本机，刷新、成功导表或重新启动后仍保留。恢复时点击该文件的红色方框，或右键选择「恢复自动判断」。蓝色强制增量标记同样会保留。

日常使用「增量导表」还是「全量导出」？

增量导表：用于日常修改，导出 SVN 检测到修改或被手动强制加入的 Excel，并跳过不导表文件。

全量导出：需要重新生成全部配置时使用，导出未标记为不导表的配置文件，耗时通常更长。执行前会要求确认。

先保存 Excel，再回到工具刷新状态。一次只能执行一个导表任务，运行期间按钮暂时不可操作。

改了 Excel 却没有增量，或列表突然空了？
  1. 确认 Excel / WPS 中已保存修改。
  2. 确认当前版本和文件路径正确，再点击「刷新状态」。
  3. 清空搜索框，点击「全部表格」，排除字母、搜索或「只看增量」筛选的影响。
  4. 检查文件是否被标记为红色不导表；需要导出时恢复自动判断，或改为强制增量。

如果日志提示 SVN 检测失败，应先解决该错误。首次导表也可以按项目需要使用全量导出。

05 打开 Excel / Sheet

如何直接打开需要的 Sheet？

在顶部切换到「Sheet 模式」，找到目标 Sheet，点击它右侧的「打开」。工具会尝试打开所属工作簿并激活该 Sheet；成功后会提示已定位的名称。

「Excel 模式」的打开按钮只负责打开工作簿，不指定 Sheet。可搜索中文表名、英文配置名、Sheet 名或说明来找表。

工作簿打开了，为什么没有切到目标 Sheet？

自动定位需要支持自动化接口的 Microsoft Excel 或 WPS。若当前环境不支持，工具会提示已打开工作簿但无法自动定位，此时请手动切换 Sheet。

其他原因会给出具体提示：Sheet 名不存在时核对 config.xml 的 sheet；Sheet 隐藏时先取消隐藏；若软件有弹窗、文件损坏或被占用，先处理后再重试。

06 错误排查

出现「导表已停止 / 导表未完成」后怎么处理？
  1. 先看右侧错误摘要，确认涉及的文件、Sheet、行号或字段。
  2. 点击「查看详细日志」查看上下文；需要他人协助时点「复制日志」，附上当前版本名和本次操作。
  3. 如果是重复 ID、缺失字段或表数据错误，按提示修改 Excel 并保存。
  4. 如果是脚本找不到、Python 错误或环境异常，核对工具路径和项目环境，必要时联系工具维护人员。
  5. 修复后重新导表，确认成功再提交 SVN。
任务失败时，部分输出可能已经生成。不要把“已开始导表”当作成功；需要检查输出并在修复后重新导出。
错误日志里的 row、id、Traceback 是什么意思？

row 通常指脚本报告的数据行，id 常用于定位键值或字段；行号是否包含表头以项目脚本为准。重复索引或重复 ID 要回到对应表检查。

Traceback 是 Python 脚本异常信息，本身不是问题原因。展开日志查看具体异常，把完整上下文交给维护人员；不要只截取标题。

长时间没有新日志，是不是卡住了？

先检查是否有 SVN、Excel 或脚本弹窗等待处理；全量导出也可能耗时较长。运行期间不要反复点击导表。

确认异常时记录最后的日志和当前版本，再联系维护人员。工具有超时处理，但没有手动取消按钮；强行关闭后需检查输出文件，重新打开并核实状态后再执行。

07 提交与日常使用

导表成功就等于提交 SVN 成功吗？

不是。导表负责生成文件；提交还需要点击「提交SVN」，核对需要提交的 Excel 和生成文件、填写提交说明，然后点击「确认并拉起提交」。

最后在 TortoiseSVN 窗口完成提交，并确认 SVN 返回成功。不要只看工具里的“已唤起提交流程”就认为上传完成。

“不导表”只影响导出范围，不会自动把文件排除出 SVN 提交列表。提交时仍需检查勾选范围。
之后怎么打开指南？可以不每次弹出吗？

主界面点击「使用指南 / FAQ」，或按 F1 随时打开。缺少 SVN 的提示和导表错误摘要旁也有对应的帮助入口。

首次使用会自动打开本指南。默认只自动展示一次；如需每次启动都看，在指南底部勾选「每次启动都显示」。关闭该选项后，仍可手动打开。

独立的 faq.html 文件可直接用浏览器打开，无需启动工具或连接网络。独立阅读时不提供打开工具设置的按钮。

没有找到匹配的问题

试试「路径」「SVN」「不导表」「Sheet」「日志」，或点击清除查看全部。
